# Research: Frontend Containerization

- **Standalone**: Next's installed [output documentation](../../frontend/node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/output.md) describes traced `.next/standalone` and `server.js`; `public` and `.next/static` must be copied separately. Prefer it if functionality and smaller-image checks pass; reject static export.
- **Native dependencies**: The lockfile contains platform-specific Next SWC and Sharp packages; the existing Debian builder and Alpine runtime use different C libraries. Use matching Node 24 slim bases; reject copying native modules across libc variants.
- **Dependency cache**: Copy manifest and lockfile before source, then run `npm ci` with dev dependencies available. This preserves npm's lockfile validation and source-independent layer caching; reject installing after the source copy or setting production mode before installation.
- **Environment**: Next's installed [environment guide](../../frontend/node_modules/next/dist/docs/01-app/02-guides/environment-variables.md) says `NEXT_PUBLIC_*` values are inlined during build. Public values need a rebuild to change; the Clerk secret is runtime-only and never a build argument. Whether the exact app builds without that secret is an implementation validation gate, not an established fact.
- **Networking**: `frontend/lib/api.ts`, `frontend/app/(app)/ask/page.tsx`, and `frontend/lib/voice.ts` use the public URL for browser requests, including WebSocket voice. The container's DNS name is generally not browser-resolvable; publish the backend or use an externally reachable endpoint, configure backend `FRONTEND_ORIGIN` and Clerk authorized parties, and separately probe Docker DNS. No current server-side backend flow was found.
- **Runtime**: Next's installed self-hosting guide describes filesystem caching; give only required cache paths write permission to the non-root user. Verify asset serving, runtime writes, Clerk middleware, signal handling, and native module loading.
- **Build prerequisites**: `next/font/google` fetches fonts, and dependencies require registry access. A successful build without network access is not assumed. Real Clerk and backend credentials are needed for authenticated end-to-end validation, not committed artifacts.
